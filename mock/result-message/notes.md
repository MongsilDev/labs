# 대회 결과 메시지 시안 메모

`node mock/result-message/render.mjs`로 PNG를 모두 다시 그립니다. 레포에 next/og 의존성이 설치돼 있지 않아 `roundImage`와 같은 색, 글꼴, 크기를 HTML로 옮겨 Playwright로 캡처했습니다.

## 공통 조건

- 가짜 대회 "시험 대회", 8팀, 4라운드 포인트제입니다. 라운드마다 운영자가 게임 결과 CSV를 올리고 2분 뒤 봇이 결과를 올린다고 놓았습니다.
- 데스크톱 캡처는 4라운드가 끝난 상태, 휴대폰 캡처는 2라운드가 끝난 상태입니다. `A-select.png`는 4라운드가 끝난 상태라 select 항목이 5개입니다.
- 메시지 수는 봇 메시지만 셉니다. 순위 행 수는 화면 안에 행 전체가 보이는 것만 셉니다.
- 순위 이미지의 기준 폭은 `roundImage`의 720px에서 600px로 줄였고 글자 크기는 그대로 뒀습니다. 560px에서는 A안 이미지의 팀 이름 칸이 174px라 "팀 이름이 긴 팀"(195.8px)이 말줄임돼 600px로 늘렸습니다. 변동 열은 52px에서 48px로 줄였습니다. A, B, C 시안과 F1, F2, F3 이미지에 모두 같은 폭을 씁니다.
- 짐작한 크기: 데스크톱 Container 최대 폭 600px, 이미지 1장은 Container 폭에 맞춤(566px). 휴대폰 이미지 폭은 284px(`round-og.tsx` 주석의 약 300px와 비슷). MediaGallery에 2장을 넣으면 두 장이 가로로 나란히 놓이고 칸마다 잘려 보인다고 놓았습니다. 실제 디스코드에서 크기가 다를 수 있습니다.
- 봇 코드(`commands/tournament.py`)는 이 레포에 없어, 아래 함수 변경은 함수 이름만 보고 적은 것입니다.

## A안, 메시지 하나

- 4라운드가 끝났을 때 남는 봇 메시지: 1개
- 한 화면: 데스크톱 메시지 1개, 순위 행 8개(작성자 줄은 화면 위로 밀림) / 휴대폰 메시지 1개, 순위 행 8개
- 메시지 구성: Container에 누적 순위 이미지와 다음 라운드 줄만 두고, 그 아래 Action Row 두 개에 select와 링크 버튼 "순위표"를 둡니다. 대회 이름과 진행 상황은 이미지 머리글에만 있습니다.
- 순위 이미지는 F1 표기에서 순위 점수 열을 뺐습니다. 열은 순위, 팀, 킬 점수, 총점, 변동입니다.
- 바뀌는 함수
  - `notice_view`: 누적 순위 이미지, 다음 라운드 줄, select, 링크 버튼을 담는 하나의 view가 됩니다.
  - `round_view`: 없앱니다. select로 고른 라운드의 게임 순위 이미지를 ephemeral로 보내는 응답을 새로 만들어야 하고, 라운드 하나의 게임 순위 이미지는 지금 `roundImage`가 그리지 않으니 웹 쪽에 새 이미지 경로가 필요합니다.
  - `post_round`: 이전 메시지를 지우고 새 메시지를 올린 뒤 메시지 ID를 저장합니다.
  - `tick`: 개요 메시지 수정이 없어집니다.
- 재시작 뒤: select를 `DynamicItem`으로 등록하고 custom_id에 대회 코드와 조를 넣으면 동작합니다. 링크 버튼은 봇과 상관없이 동작합니다.
- 디스코드에서 Action Row 하나에는 select 하나 또는 버튼 최대 5개만 넣을 수 있어, select와 링크 버튼을 Action Row 두 개로 나눴습니다.

## B안, 지금 구성 정리

- 4라운드가 끝났을 때 남는 봇 메시지: 5개(개요 1, 라운드 4)
- 한 화면: 데스크톱 메시지 1개, 순위 행 8개 / 휴대폰 메시지 2개, 순위 행 10개(위 메시지 2행 + 아래 메시지 8행)
- 바뀌는 함수
  - `notice_view`: 다음 라운드 줄과 금지 실험체 줄을 뺍니다.
  - `round_view`: 이미지와 다음 라운드 줄, 금지 실험체 줄만 둡니다. 링크 버튼을 뺍니다.
  - `post_round`: 시안은 지난 라운드 메시지에서 다음 라운드 줄을 뺀다고 놓았습니다. 지시문의 "마지막 라운드 메시지에만 표시"에서 짐작한 것이고 봇 코드로 확인하지 않았습니다. 지금 이 수정을 하지 않는다면 새로 넣어야 하고, 넣지 않으면 지난 라운드 메시지마다 다음 라운드 줄이 남습니다. C안도 같습니다.
  - `tick`: 개요 메시지에서 진행 상황 줄만 고칩니다.
- 재시작 뒤: 링크 버튼만 있어 그대로 동작합니다.
- 2라운드부터 개요 메시지가 화면 밖으로 밀려, 순위표 버튼과 CSV 안내 줄은 채널을 위로 올려야 보입니다.
- 지시문의 "다음 라운드 줄"에 금지 실험체 줄도 들어간다고 보고, 라운드 메시지에 두 줄을 같이 뒀습니다.

## C안, 라운드 메시지에 두 장

- 4라운드가 끝났을 때 남는 봇 메시지: 4개
- 한 화면: 데스크톱 메시지 2개, 순위 행 22개 / 휴대폰 메시지 2개, 순위 행 28개
- 바뀌는 함수
  - `notice_view`: 없앱니다.
  - `round_view`: 제목 Text Display와 이미지 2장, 다음 라운드 줄, 링크 버튼을 둡니다.
  - `post_round`: 라운드 하나의 게임 순위 이미지도 같이 올립니다. A안처럼 새 이미지 경로가 필요합니다.
  - `tick`: 개요 메시지 수정이 없어집니다.
- 재시작 뒤: 링크 버튼만 있어 그대로 동작합니다.
- 두 장이 나란히 놓여 한 장 폭이 데스크톱 281px, 휴대폰 140px입니다. 칸이 정사각형이라 600px 폭 이미지는 위아래가 잘려 이미지 머리글의 대회 이름이 가려집니다. 휴대폰에서는 글자가 5~7px라 읽을 수 없습니다. 이미지를 누르면 크게 볼 수 있습니다.
- 개요 메시지가 없어 "이 채널에 올린 게임 결과 CSV는 순위에 반영됩니다." 안내가 빠집니다.

## 휴대폰 글자 크기

390 폭 휴대폰 시안에서 잰 값입니다. 화면 크기 = 이미지 안 글자 크기 × 화면에 표시된 이미지 폭 ÷ 이미지 원본 폭입니다. 이미지 안 글자 크기는 열 머리글 21px, 팀 이름 29px이고, 원본 폭은 기준 폭(720 또는 600)입니다. C안은 정사각형 칸을 채우도록 늘린 폭을 표시된 폭으로 썼습니다.

| 안 | 표시된 이미지 폭 | 열 머리글 720 → 600 | 팀 이름 720 → 600 |
| --- | --- | --- | --- |
| A | 284px | 8.3px → 9.9px | 11.4px → 13.7px |
| B | 284px | 8.3px → 9.9px | 11.4px → 13.7px |
| C | 720 기준 148px, 600 기준 140px | 4.3px → 4.9px | 6.0px → 6.8px |

## 점수 표기

2라운드 누적 순위입니다. 표의 숫자는 600 폭 기준으로 잰 정수 자리 오른쪽 끝의 위치입니다.

| 안 | 킬 점수 열 | 총점 열 | 정수 자리 |
| --- | --- | --- | --- |
| F1 | 379 | 488 | 열마다 한 위치. 순위 점수 열도 300 한 위치 |
| F2 | 380.3, 380.5 | 488.9, 489.4 | 0.5px 안에서 맞음 |
| F3 | 380.5, 404 | 489.4, 520 | 정수 값만 23~31px 오른쪽으로 밀림 |

- F1은 정수 오른쪽에 ".5"가 들어갈 고정 폭 칸을 두고, 열 머리글은 그 칸의 오른쪽 끝에 맞춥니다. 머리글 오른쪽 끝과 숫자 열 오른쪽 끝은 킬 점수 404, 총점 520으로 같습니다. A안 이미지도 같은 규칙입니다.
- F1은 순위 점수 열이 늘어 팀 이름 칸이 600 기준 124px입니다. "팀 이름이 긴 팀"(195.8px)은 말줄임되고, 기준 폭을 600으로 늘려도 담지 못합니다. 순위 점수 열을 뺀 A안 이미지는 214px, F2와 F3은 236px로 말줄임 없이 들어갑니다. C안의 게임 순위 이미지도 순위 점수 열이 있어 194px로 2px 모자랍니다.
- F1은 Pretendard의 tabular-nums를 씁니다. 같은 크기에서 "1111"과 "0000"의 폭이 같은 것을 확인했습니다.
- 300px 사본에서 글자 크기는 팀 이름 14.5px, 킬 점수 13px입니다.
